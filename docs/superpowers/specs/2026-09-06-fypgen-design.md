# fypgen — FYP Report Generator (Local, Free Forever)

- **Date:** 2026-09-06
- **Status:** Approved design (brainstorming complete)
- **Competitive context:** `scrape.md` — competitor MonoEd Africa (monoed.africa)

---

## 1. Purpose

A free-forever Final Year Project (FYP) report generator for Nigerian university students. It competes head-on with MonoEd Africa's ₦4,900 flagship FYP tool by removing the paywall entirely and running on the student's own machine.

**Core moves:**

- **Free forever, no strings** — no accounts, no payments, no credits, no telemetry.
- **Local-first** — the entire app runs on the student's machine via one command (`npx fypgen`). Zero hosting and zero AI cost to us.
- **Bring-your-own API key** — the student's own Gemini/OpenAI/Anthropic key powers generation. Gemini's free tier makes it genuinely free for them.
- **Feature parity with MonoEd's FYP tool** — same intake fields, 5-chapter Nigerian structure, DOCX export, defense slides (PPTX) — plus a Q&A defense-prep appendix.

**Ethics stance (v1):** full generator — topic in, complete project out. References are AI-generated (plausible but unverified) and are labeled as such: *"AI-generated references — verify before submission."* Citation verification is deferred to v2.

**Success bar (learning project):** a polished, working product students can actually use — shipping quality over adoption metrics.

## 2. Architecture

One npm package, one codebase, three parts:

```
fypgen/
├── server/        # Hono server (~100 lines): serves the built SPA,
│                  #   proxies AI streaming calls. Nothing else.
├── web/           # Vite + React SPA: the whole product
│   ├── wizard/    # Topic → outline → generation → review → export flow
│   ├── generate/  # Streaming chapter rendering, per-chapter regenerate
│   └── export/    # DOCX + PPTX builders (client-side)
└── cli/           # `npx fypgen` entry: boot server, open browser
```

**Runtime flow:**

1. Student runs `npx fypgen`.
2. CLI boots the Hono server on a free localhost port.
3. CLI opens the default browser automatically.
4. Everything from there is the SPA.

**Key handling:** the API key lives in browser localStorage and is sent per-request to the local proxy. It is never written to disk server-side and never logged.

**Server responsibilities (exhaustive):** serve static SPA files; proxy AI requests (provider adapters run server-side in the proxy so browser CORS quirks vanish). No database, no persistence, no accounts.

**Project state:** localStorage — saved after every generation step; on relaunch the student returns exactly where they left off.

**Distribution:** `npx fypgen` from npm. A single self-contained binary (Bun compile / Node SEA) is a possible later packaging upgrade, not v1.

## 3. AI layer

### 3.1 Provider adapters

Three providers, one interface:

```ts
interface AIProvider {
  testKey(key: string): Promise<{ ok: boolean; error?: string }>
  streamChapter(prompt: PromptParts): AsyncIterable<string>
}
```

- **Gemini** — default recommendation (genuinely free tier).
- **OpenAI** and **Anthropic** — supported alternatives.
- Model choice: sensible per-provider defaults, with an advanced override in settings.

### 3.2 Prompt pipeline

Every generation call is a three-part prompt:

1. **System prompt** — Nigerian FYP conventions: 5-chapter structure, academic register ("write as a Nigerian final-year student — formal, not stilted"), chapter word targets (Ch. 1–2 ~2,500 words; Ch. 3–5 ~3,000–5,000), formatting conventions.
2. **Project context block** — topic, student name, matric, university, department, supervisor, degree, session, plus the approved (student-edited) outline so every chapter knows the whole document's shape.
3. **Chapter spec** — the chapter's sections with one-line descriptions, plus any regeneration nudges.

### 3.3 Streaming

The server proxy pipes the provider's streaming response to the browser (SSE-style). Chapter text streams into a live-rendered panel.

**Mid-stream failure:** partial text is preserved; a **Continue** action re-prompts the model with the partial text appended. No lost work.

### 3.4 References

APA 7 references section generated by the model, with in-text citations. The section carries a visible label: *"AI-generated references — verify before submission."*

### 3.5 Student-side cost

One chapter ≈ 6–8k output tokens; a full FYP fits comfortably in Gemini's free daily limits. Onboarding copy states this plainly ("a full project uses about 4% of your daily free allowance").

## 4. User flow

### 4.1 Onboarding (one screen)

- 30-second explainer, then **connect your AI**: provider picker (Gemini / OpenAI / Anthropic), link to each platform's key page, paste field.
- **Test key** button fires a tiny 1-token request before saving.
- The key is the account — no signup, no email.

### 4.2 Project setup (one form)

Topic, student name, matric number, university, department, supervisor, degree, session/academic year. Same fields MonoEd asks for — zero switching cost.

### 4.3 Outline proposal

- AI drafts the full 5-chapter outline (section + sub-section headings, one-line descriptions) before any prose.
- Student can edit any heading, reorder, or delete sections. **Regenerate outline** button.
- This is where quality is decided — cheap to iterate, expensive to skip.

### 4.4 Chapter-by-chapter generation

- Generate chapters one at a time, or **generate all sequentially**.
- Each chapter streams live, rendered with proper heading hierarchy.
- Per-chapter controls: **regenerate** (optionally with a nudge — "make methodology more quantitative"), inline edit after generation.
- Visual state per chapter: pending → streaming → done.

### 4.5 Review & edit

Full document view — all chapters assembled, editable inline. Word count per chapter and total.

### 4.6 Export

Two actions: **Download DOCX** and **Download Defense Slides (PPTX)**.

### 4.7 Out of scope for v1 (the v2 list)

Supervisor-fix mode, citation verification against real databases, multi-project management, PDF export.

## 5. Export

### 5.1 DOCX (`docx` npm package, client-side)

- **Preliminary pages:** title page (standard Nigerian university layout: university, department, topic, student name/matric, supervisor, degree, session), declaration & certification pages, abstract, table of contents.
- **Body:** 5 chapters, CHAPTER ONE/TWO… heading style, numbered headings, double-spaced, Times New Roman 12, justified, 1" margins, page numbers.
- **References:** APA 7, hanging indent.

### 5.2 PPTX (`pptxgenjs`, client-side)

- ~12–15 slides: title → background/problem → objectives → scope → methodology → results → conclusion → recommendations → thank-you/Q&A.
- Clean academic template: dark-on-light, one accent color; title + content layouts only.
- **Q&A prep appendix:** final slides list likely defense questions per chapter (generated) — differentiator also played on by MonoEd.

---

## 6. Error handling

**Fail loud, never lose work.**

- **Invalid key / quota exceeded** → clear banner with the exact provider error + "fix key" link back to settings.
- **Stream drops mid-chapter** → partial text kept, **Continue** re-prompts with partial text.
- **Export failure** → surfaced error with retry; document state is already in localStorage.
- **Crash / tab close** → relaunch restores exact state from localStorage.
